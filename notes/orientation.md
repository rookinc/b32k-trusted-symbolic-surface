# Orientation

B32K belongs under methods because it is infrastructure, not a single domain result.

It can support Thalean graph theory, CoRI provenance, LLM context design, coherence auditing, and future symbolic registry work.

The current motivating idea is that LLMs may benefit less from raw context expansion than from constraint-bearing context. B32K may provide a stable surface where key identities, roles, relations, and boundaries are preserved before interpretation begins.

## Analogy from coherence-gap work

In the graph audit:

- raw local mimicry could imitate the target shell profile
- global coherence still failed
- decorative context did not help
- recurrent shared-cell context produced a nontrivial stress signal
- frontier and tail exposure mattered
- shuffle-null tests suggested structure mattered

The LLM analogy is only an analogy.

But it suggests a useful distinction:

- more context is not necessarily better context
- labels are not necessarily constraints
- stable symbolic incidence may help preserve complex structure across interpretation

## Near-term goal

Build the minimal machine-readable B32K registry and verification scripts.

The first implementation target is boring on purpose:

1. store the core PDFs
2. extract or generate canonical JSON/CSV/TOML registry artifacts
3. verify index uniqueness and lattice consistency
4. define a small LLM-facing surface profile
5. test whether structured symbolic context reduces drift compared with prose-only context
